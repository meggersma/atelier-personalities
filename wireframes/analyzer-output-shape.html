1
turn_id

Anchors feedback to a moment. Both views need it; cross-session stats aggregate on it.

2
span — quote + resolved offsets

The Word view attaches tracked changes to text ranges, not paragraphs. The LLM returns the quote; the backend resolves it to offsets by string-match (LLMs are unreliable at raw offsets). Dashboard ignores this field.

3
category — closed enum

The data. Cross-session trends ("compound-question rate over 6 sessions") only work if this label is stable. See taxonomy in ⑤ below.

4
severity — critical / major / minor / praise

Drives dashboard sort + Word comment color. Praise is a first-class severity: an all-redline review reads as demoralizing and wastes teachable wins.

5
ai_note — the reviewer's voice

Margin comment in Word; card body in dashboard. This is where the partner twin's style lives.

6
suggested_rewrite — optional

Becomes the literal redline (delete span, insert rewrite). Null for annotations with no fix (e.g., praise, missed-opportunity notes).

7
reviewer_id

Same schema, different twin, different annotation set — what makes side-by-side comparison cheap.
